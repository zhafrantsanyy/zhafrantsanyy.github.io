  1. Financial trading · Programmatic SEO · Global

    Gotrade

    Programmatic content only scales when the quality control is programmatic too. Every article passes the same gate before it ships.

    The challenge

    Gotrade competes in financial trading, a YMYL category where Google demands demonstrable expertise and volume alone never ranks. The mandate was a content engine that could produce instrument, market and education pages at scale, where every output still cleared originality and E-E-A-T standards without a human reading it first.

    The architecture

    1. Keyword and template map: thousands of target queries resolved into a finite set of layouts.
    2. Programmatic drafting from structured briefs and a controlled source layer.
    3. An automated quality gate: ZeroGPT originality plus an automated E-E-A-T checker. Under threshold means an automatic rewrite.
    4. Widget generation: instrument cards, price tables and comparison blocks per page.
    5. An internal link graph mapped at write time.
    6. CMS publishing, status tracking and refresh cycles as a managed pipeline.

(04)The engine

Keyword in. Ranking page out.

The programmatic content engine behind Gotrade and Tembuni: six stages, one automated quality gate and no human in the loop. The diagram runs a live simulation.

  1. Instrument, market and strategy clusters mapped to page templates. Thousands of target queries resolved into a finite set of layouts.

  2. Structured briefs generate a draft per keyword, with data, definitions and disclosures pulled from a controlled source layer.

  3. Every draft is scored against a ZeroGPT originality benchmark and an automated E-E-A-T checker. Anything under threshold goes back for a rewrite.

  4. Instrument cards, price tables and comparison blocks are built and injected into each page automatically.

  5. Contextual links are mapped across the cluster at write time, so every new page strengthens the ones already published.

  6. Publishing queue, status tracking and refresh cycles run as a managed pipeline instead of a manual editorial calendar.

(05)Shipped

Things I actually shipped.

Four public repositories: an automation pipeline, two operational dashboards and a marketplace. Every one of them started as somebody's spreadsheet.

01 / 04JavaScript

financial-reporting-pipeline

n8n · 61 nodes · ~4k lines of JS

One n8n workflow that pulls invoices, inventory and the chart of accounts out of Accurate Online, merges them with the team's Google Sheets, computes operational and financial metrics, renders self-contained HTML dashboards and delivers everything to Telegram at 07:00. Then it answers follow-up questions as a conversational analyst.

  • P&L summed from leaf GL accounts after a parent balance silently hid a large owner draw
  • Per-sheet column fingerprinting, so a September row is never read through a July column map
  • Script-free HTML dashboards, because Telegram's document viewer runs no JavaScript
  • n8n
  • LLM
  • Telegram API
  • Google Sheets

TJS Logtrade · internal dashboard for a timber broker

Next.js 15 App Router on Supabase: live stock, supplier reliability scoring, price history and a per-pallet quality-control sheet. Reads go through Server Components, writes through Server Actions, and every route sits behind two independent auth checks.
